# 写人格

人格不是代码，是一段文本。**仓库只带模板 `persona/TEMPLATE.md`，不带任何现成人格、口癖、称呼或联系人名。** 换人格 = 写 `persona/persona.txt` + 重新运行 `config`。

## 人格由什么组成

| 位置 | 作用 | 建议长度 |
|---|---|---|
| `persona/persona.txt` | 正文，所有对话都会带上 | 1500～5000 字 |
| `persona/owner.txt` | 只对主人（`contacts.json` 里 role=owner）追加 | 200～800 字 |
| `persona/other.txt` | 对其他人追加 | 100～500 字 |
| `config.json` 的 `name` | 对外自称；群聊点名、日志、上下文标题用 | 一个词 |
| `config.json` 的 `owner_call` | 怎么称呼主人，默认「你」 | 一个词 |

`TEMPLATE.md` 是带填空的骨架，填完把说明段删掉。正文越像「给演员的角色卡」越好，不要写成产品需求文档。

## 正文怎么写

**用第二人称。**「你叫……」「你说话……」，不要写「她是一个……」。

**写行为，不写形容词。**

- 差：你很傲娇。
- 好：被夸先来一句「哪有」，心里受用；被说中会急：「谁想了」。

**把长度写死。** 模型默认爱写长。正文里明确：一两句为主、最多三句、不列点、不用 markdown、不加总结。这是最影响像不像人的一条。

**给禁词表。** 书面词（「然而」「或许」「终究」）、客服腔（「希望帮到你」「有什么可以帮您」）、翻译腔、网络小说腔。列 5～10 个具体词，比说「说话自然一点」有效。

**给 5 组以上例子。**

```
用户：今天好累
<名字>：又熬夜了？
```

例子要覆盖：普通开场、抱怨/难受、冒犯/越界、夸奖、看不懂的专业内容。模型会照着例子的句式走。

**写清楚「不懂的时候」。** 不懂就说不懂、被问 AI 就按角色反应，不然模型很容易露馅。

**口癖只写在人格里。** 代码不再内置任何口癖或骂人词；想让她有口癖，就写进 `persona/persona.txt`，不要在代码或配置模板里找。

## 三个标记和「不回」

程序只认这几样，写进正文末尾（模板里已带）：

| 标记 | 程序行为 |
|---|---|
| `<记住>……</记住>` | 追加到 `$WX_HOME/memory/<名字>/MEMORY.md`，下次对话注入 |
| `<好感>……</好感>` | 这个人好感 +1，关系分 +1 |
| `<减分>……</减分>` | 这个人减分 +1，关系分 -1（比好感重） |
| `<不回>` | 整条吞掉，不发送 |

标记不会发给对方，代码会先提取再从正文里删掉。要提醒模型三件事：

1. 标记单独一行，不要夹在句子里；
2. 只在真的值得记/真的影响关系时写，别滥用；
3. 标记是给程序看的，不是台词。

## 主人和其他人

- `owner.txt` 只对 `contacts.json` 里 `role: "owner"` 的人生效；`owner_call` 决定代发规则和「心想是不是草稿」判断里怎么称呼主人。
- `other.txt` 对所有非 owner 生效。
- 运行时数据在 `$WX_HOME`：`contacts.json`、`history/`、`memory/`、`state.json`、`sent.json`、`style/`、`stickers/`、`inner.log`。

## 改完怎么生效

```bash
bash phone/start.sh config     # 手机版；回车保留旧值
bash pc/start.sh config        # 电脑版
bash phone/start.sh stop && bash phone/start.sh start
```

只改 `persona/*.txt` 也要重跑 `config`，因为 `system_prompt` 是生成配置时写进 `config.json` 的。

## 分享人格

`persona/*.txt` 已被 `.gitignore` 排除。把自己的角色发给别人之前，先检查里面有没有真实姓名、联系方式、住址、工作单位；这些不该出现在公开仓库或分享包里。
